# Fast local decoding for small and dense models: audit and research

Date: 2026-10-14. Target machine: RTX 5070 Ti Laptop 12 GB (Blackwell, sm_120), Core Ultra 9 275HX (8 P + 16 E cores), 63 GB RAM. Stack: telecode supervising llama-server (upstream base `fcac19079`, b11609 line, plus our working-tree patches `0001`-`0003`).

How to read the evidence tags:
- **[src]** verified by grepping `D:\Projects\Telecode\build\llama.cpp` (the working tree, which includes our uncommitted patches `0002`/`0003`).
- **[tc]** verified in `llamacpp\argv.py`, `llamacpp\config.py`, `tray\qt_sections.py` or `settings.json`.
- **[measured]** a third party ran it and published the setup. Still one run on one machine unless noted.
- **[vendor]** the project's or a vendor's own claim or paper headline. Not independent.
- **[unverified]** a secondary blog, a forum post, or something I could not confirm. Do not rely on it without a re-check.

Nothing was run on this machine: no model, no GPU process, no downloads beyond web pages.

## 0. What the audit found in our own config (read this first)

| Finding | Evidence | Why it matters |
|---|---|---|
| `qwen3.8-27b` (dense, IQ3_XXS + MTP head) puts **`output.weight` on the CPU** (`override_tensor: ^token_embd\.weight=CPU,^output\.weight=CPU`). | [tc] `settings.json` lines 159-163 | The output head is a vocab x hidden matmul run on every generated token. If the model's head is untied, it is executed on the CPU for each token (and for each verified draft token). `token_embd` on CPU is harmless (a row lookup); `output.weight` on CPU is not. Probably done to fit 12 GB with 80k q4_0 KV; it may be costing a double-digit share of decode time. **Measure with `llama-bench`/the Speed Test: head on GPU and a few FFN layers moved to CPU (`--n-cpu-ffn`) instead.** Not measured here. [unverified: whether this model's head is tied, its vocab size, the actual cost] |
| Global `spec_type` is `"none"`; `spec_default` false. Per-model spec settings were not visible in the excerpt I read. | [tc] `settings.json` lines 98-99 | Dense models gain most from MTP (see section 3). Check the 27B entry for `draft_n` / `spec_type`; `ctx_size_spec: 60000` suggests a spec profile exists. |
| KV is `q4_0` for both K and V on the 27B. | [tc] `settings.json` lines 116-117, 164-165 | Rotation (below) makes q4_0 usable, but K is the sensitive half. `k8v4` (K q8_0, V q4_0) is the usual compromise. See section 1, row KV. |
| Threads: `threads 8`, `threads_batch 24`, no CPU mask/range set at global level. | [tc] `settings.json` lines 48-49 | 24 batch threads span P and E cores. For a fully GPU-resident small model the CPU only launches kernels and runs the sampler; fewer threads and no E cores are usually better. When the CPU computes (partial offload) pin to the 8 P cores. `llamacpp\cpu_topology.py` (untracked) already exists for detection. |
| The Core Ultra 9 275HX has **no AVX-512 and no AMX** (P cores have no hyper-threading, so 8 P threads). | Instruction lists from CPU-id dumps, not Intel's sheet: [notebookcheck](https://www.notebookcheck.net/Ultra-9-275HX-vs-Ryzen-AI-9-HX-370_18886_17543.247596.0.html), [valid.x86.fr](https://valid.x86.fr/7rlhz4) [unverified, absence-of-evidence] | CPU kernel work should target AVX2 + AVX-VNNI. Any AVX-512 / AMX advice in the literature does not apply to this CPU. |

## 5. Decision: what is really better for us

| Option | Better than what we have for a 12 GB Blackwell laptop? | Basis | Route |
|---|---|---|---|
| MTP tuned per dense model (n-max 2-3, p-min about 0.85) + adaptive policy | **Yes, large** (1.7x measured on a 3090 27B) | [measured] | Setting only |
| MTP chained with ngram-mod for agent loops | **Likely yes** (free drafts when text repeats) | upstream docs; no independent number | Setting + preset |
| Output head on GPU instead of CPU for the 27B | **Possibly large**, unmeasured | config finding | Setting; benchmark |
| NVFP4 weights | **Prefill only**, +43-68% on a 5090; unknown on sm_120 laptop | [unverified] | Download + benchmark |
| EAGLE-3 / DFlash / DSpark heads for small (<=14B) models | **Likely yes if a head exists**; claims are vendor | [vendor] | Flag exists; need head GGUF |
| Suffix-tree drafting | Possible for agentic loops; unproven locally | [vendor] | L patch |
| K8V4 / rotation KV | Quality and context win, speed neutral | [unverified] | Preset |
| Message-boundary checkpoints | Latency win on long agent histories | Strata design | M patch |
| EXL3, vLLM, TensorRT-LLM, MLC | **No** (no CPU offload, VRAM, or no 12 GB data) | section 4 | not recommended |
| ik_llama.cpp, mistral.rs | **Unproven**; A/B only | section 4 | separate binary, M |
